PASO 3️⃣: USUARIO VE DASHBOARD  
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PASO 4️⃣: USUARIO ELIGE UNA OPCIÓN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

              ↓
        Abre página de control
              ↓
        Selecciona persona
        Presiona ABRIR


PASO 5️⃣: FRONTEND ENVÍA AL BACKEND
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Petición HTTP:
  POST /api/registros
  {
    "nombre": "Juan García",
    "tipo": "entrada"
  }


PASO 6️⃣: BACKEND PROCESA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Backend hace:
  ✓ Verifica JWT (¿es usuario válido?)
  ✓ Consulta BD (¿existe la persona?)
  ✓ Crea registro
  ✓ Publica en MQTT


PASO 7️⃣: ESP32 ABRE CERRADURA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Proceso:
  MQTT → ESP32 → GPIO 26 → TRIAC → ⚡ 
  
  Resultado: 🔓 PUERTA ABIERTA (3-5 seg)


PASO 8️⃣: DEVUELVE RESPUESTA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Backend responde:
  ✅ {
      "status": "ok",
      "mensaje": "Acceso registrado"
     }

Frontend muestra: ✅ ¡PUERTA ABIERTA!

🔒 SEGURIDAD - 3 NIVELES

================================================================================

NIVEL 1: FRONTEND (Lo que VES)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Valida que rellenes campos correctamente
- Rechaza emails mal formados
- Requiere contraseña mínimo 6 caracteres
- No te deja enviar datos vacíos


NIVEL 2: BACKEND (Procesamiento)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Verifica JWT token (¿eres realmente quién dices?)
- Valida nuevamente todos los datos
- Encripta información sensible
- Registra TODO en logs


NIVEL 3: BASE DE DATOS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Guarda datos ENCRIPTADOS
- Las contraseñas están con HASH (no recuperables)
- Cada acción queda registrada
- Protección contra SQL injection


================================================================================

⚡ EL FLUJO DEL "ABRIR PUERTA" EN 7 PASOS

================================================================================

1. Usuario presiona ABRIR
   ↓
2. Frontend envía: POST /api/registros
   ↓
3. Backend recibe y verifica JWT
   ↓
4. Backend consulta: ¿existe la persona?
   ↓
5. Backend publica en MQTT: "Abre puerta"
   ↓
6. ESP32 recibe mensaje:
   - Activa GPIO 26
   - 110/220V entra a TRIAC
   - Solenoide se energiza
   - ⚡ CERRADURA ABRE
   ↓
7. Backend responde: ✅ OK
   Frontend muestra: "Puerta abierta"

¿DUDAS COMUNES?

================================================================================

P: ¿Dónde se guardan los datos?
R: En el archivo "instance/app.db" (Base de datos SQLite)

P: ¿Cómo se comunica el Backend con ESP32?
R: Por MQTT. Backend publica en "control/acceso" y ESP32 escucha

P: ¿Qué pasa si pongo contraseña incorrecta 5 veces?
R: La cuenta se bloquea 15 minutos

P: ¿Se puede ver quién accedió y cuándo?
R: Sí, está todo registrado en BD con fecha/hora

P: ¿Qué pasa si falla el ESP32?
R: Hay botón manual para abrir puerta (se registra igual)

P: ¿Cómo es seguro?
R: JWT + Encriptación + Validaciones + Logs de auditoría
